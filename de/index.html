Live · Offset-Paging gegen eine Tabelle, die sich ständig ändert

Beide Bahnen lesen dieselben 11 Zeilen, dieselben zwei Schreibvorgänge treffen mitten im Lauf ein, und nur eine Bahn liegt richtig. Drücken Sie Play. Die allgemein verwendbare Lösung liegt auf GitHub als postgrest-keyset-page.

OFFSET n LIMIT 30 Duplikate · 0 übersprungen
10987654321
WHERE id < last_seen LIMIT 30 Duplikate · 0 übersprungen
10987654321

Zeile 11 kommt dazu, dann wird Zeile 6 gelöscht, beides mitten im Durchlauf. Genau die Abfolge, die das in der Praxis kaputt gemacht hat.

Die technische Lehre: Cursor-Paginierung vermeidet verschobene Offset-Fenster, wenn während eines Durchlaufs Zeilen eingefügt oder gelöscht werden.

Ein toter Browser sieht genauso aus wie ein gesunder.

Der Watchdog startet den Scraper erst neu, nachdem er über ein Zeitfenster echte CPU-Aktivität bestätigt hat. Zu prüfen, ob die Prozess-ID noch existiert, beweist nichts.

Ein Nichts ist keine Null.

„Nie gemessen“ und „gemessen, und es ist null“ sehen in einer Tabelle gleich aus und bedeuten für ein Bewertungsmodell das Gegenteil.
