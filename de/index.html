01

Team Gold CRM

Next.js / TypeScript / PostgreSQL

CRM-Fallstudie · Systemcode privat

Code und Dokumentation ↗
Problem & Lösung
Ein CRM für Lead-Import, Vertriebsaufgaben, Browser-Telefonie und E-Mail-Abläufe bei Team Gold. Die öffentliche Fallstudie erklärt das private System und enthält drei isolierte Hilfsfunktionen.
Technische Entscheidung
Next.js-Serverrouten verbinden Supabase Auth und PostgreSQL mit Telnyx und Resend. Provider-Zugangsdaten gehören auf den Server; das Frontend erhält den für die Sitzung vorgesehenen Telefonie-Token.
Prüfung & Grenzen
Die öffentlichen Tests prüfen Telefonnummern, E-Mail-Normalisierung und Empfänger-Deduplizierung. Sie ersetzen keine Integrationstests des privaten CRM und keine Prüfung der produktiven RLS-Regeln.

02

git-secret-scan

Python / Git / GitHub Actions

Python-Werkzeug · öffentlich

Code und Dokumentation ↗
Problem & Lösung
Ein Pre-Commit-Hook und eine GitHub Action erkennen zehn Arten von Zugangsdaten. Fundstellen werden mit maskierten Werten ausgegeben; Git-Fehler führen zu einem Fehlerstatus.
Technische Entscheidung
Index, Arbeitsbaum, Commit-Bereich und Historie liefern Datei-Bytes an denselben Scanner. Tests prüfen auch ungewöhnliche Dateinamen und die Hook-Installation in Worktrees.
Prüfung & Grenzen
Unit-, Integrations- und Property-Tests sowie ein synthetischer, beschrifteter Benchmark. Dessen Ergebnisse gelten für diesen Korpus; Regex-Muster, Ausnahmen sowie Größen- und Binärfilter begrenzen die Erkennung.

03

AutoLM

Python / PyTorch / Tokenisierung

Forschungsprojekt · experimentell

Code und Dokumentation ↗
Problem & Lösung
Ein Decoder-only-Transformer mit eigener BPE-Tokenisierung, Trainingspipeline und Evaluation. Ein kleines Workflow-Modell erzeugt n8n-Gerüste aus Textbeschreibungen.
Technische Entscheidung
Eine kompakte Zwischenform trennt die Generierung von wiederholtem Workflow-JSON. Die Evaluation prüft JSON, Node-Typen, Verbindungen und n8n-Import; eine Nearest-Neighbor-Baseline dient zum Vergleich.
Prüfung & Grenzen
Tests vergleichen Attention- und Tokenizer-Implementierungen und prüfen Checkpoint-Resume. Versionierte Messungen unterscheiden Einzelversuche und mehrere Kandidaten. Importierbare Gerüste sind keine geprüften, ausführbaren Automationen.

04

Windows Screen Time Manager

PowerShell / C# / Win32

Windows-Werkzeug · Integration offen

Code und Dokumentation ↗
Problem & Lösung
Ein systemweiter Bildschirmzeit-Zähler mit Tageslimits, Pausen, Bonuszeit und Verwaltungsoberfläche. Ein geplanter SYSTEM-Task erfasst aktive Sitzungen über WTS und einen C#-Hilfsprozess.
Technische Entscheidung
Geschützte Konfiguration und Laufzeitdaten sind von der lesbaren Statusanzeige getrennt. Der Installer setzt ACLs und weist verknüpfte Pfade zurück. Zähler und Konfiguration werden über temporäre Dateien ersetzt.
Prüfung & Grenzen
Automatisierte Syntax- und reine Logikprüfungen ergänzen die dokumentierten manuellen Tests. Der vollständige Installer- und Sitzungsablauf muss noch auf einem frischen Windows-Testsystem geprüft werden.
