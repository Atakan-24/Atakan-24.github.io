01

Team Gold CRM

Next.js / TypeScript / PostgreSQL

CRM case study · system code private

Code and documentation ↗
Problem & implementation
A CRM for lead imports, sales queues, browser calling and email workflows at Team Gold. The public case study describes the private system and includes three isolated helpers.
Design decision
Next.js server routes connect Supabase Auth and PostgreSQL with Telnyx and Resend. Provider credentials stay server-side; the frontend receives the calling token intended for its session.
Verification & limits
Public tests cover phone and email normalization and recipient deduplication. They do not verify the private CRM integrations or deployed RLS policies.

02

git-secret-scan

Python / Git / GitHub Actions

Python tool · public source

Code and documentation ↗
Problem & implementation
A pre-commit hook and GitHub Action detect ten credential patterns. Findings contain masked values; Git failures produce an error status.
Design decision
Index, working tree, commit range and history feed file bytes into one scanner. Tests include unusual filenames and hook installation in linked worktrees.
Verification & limits
Unit, integration and property tests plus a labelled synthetic benchmark. Results apply to that corpus; regex patterns, exemptions and size/binary filters limit detection.

03

AutoLM

Python / PyTorch / tokenization

Research project · experimental

Code and documentation ↗
Problem & implementation
A decoder-only transformer with custom BPE tokenization, a training pipeline and evaluation. A small workflow model generates n8n skeletons from text descriptions.
Design decision
A compact intermediate representation separates generation from repetitive workflow JSON. Evaluation checks JSON, node types, connections and n8n import, with a nearest-neighbor baseline for comparison.
Verification & limits
Tests compare attention and tokenizer implementations and verify checkpoint resume. Saved evaluations distinguish single samples from multiple candidates. Importable skeletons are not verified executable automations.

04

Windows Screen Time Manager

PowerShell / C# / Win32

Windows utility · integration pending

Code and documentation ↗
Problem & implementation
System-wide screen-time tracking with daily limits, breaks, bonus time and an administration interface. A scheduled SYSTEM task reads active sessions through WTS and a C# helper.
Design decision
Protected configuration and runtime state are separate from the user-readable status display. The installer applies ACLs and rejects linked paths. State and configuration use temporary-file replacement.
Verification & limits
Automated syntax and pure-logic checks complement documented manual tests. The complete installer and session flow still needs verification on a fresh Windows test system.
